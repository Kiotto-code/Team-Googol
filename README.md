# Team-Googol FastAPI app

Simple FastAPI backend + Jinja2 frontend served from the same server, using SQLite.

## Run locally (Python 3.10.12)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Open http://127.0.0.1:8000 for a minimal UI.

## Admin SPA configuration

The React admin panel lives in [`admin-panel/`](admin-panel) and is served by FastAPI from `/admin-panel` when a production build exists.

### Environment variables

1. Copy the template into the Vite project:
   ```bash
   cp .env.example admin-panel/.env
   ```
2. Adjust the values for your environment. The SPA reads the following variables (all prefixed with `VITE_` because they are embedded at build time):
   - `VITE_API_BASE_URL` &mdash; Full URL for REST requests (e.g. `http://127.0.0.1:8000/api/v1/admin`).
   - `VITE_WS_URL` &mdash; Base WebSocket URL (protocol + host). Leave empty to infer it from the browser location.
   - `VITE_DEFAULT_TZ` &mdash; Default timezone for new sessions (IANA identifier). Leave empty to fall back to the browser timezone.

For production builds, create `admin-panel/.env.production` (or set the variables in the shell) before running the build command so the correct values are embedded into the static assets.

### Building and hosting behind `/admin-panel`

```bash
cd admin-panel
npm install
npm run build
```

The build artifacts are emitted to `admin-panel/dist`. When that directory exists, the FastAPI app automatically serves:

- `/admin-panel` for the SPA entry point (already configured with `base: "/admin-panel/"` in `vite.config.ts`).
- `/admin-panel/assets/*` for static assets generated by Vite.

Deploy the contents of `admin-panel/dist` alongside the FastAPI app (or behind the same reverse proxy) so requests to `/admin-panel` and `/admin-panel/assets/*` are routed to those static files.

## API

- Users: GET/POST /users
- Items: GET/POST /items
- Boxes: GET/POST /boxes
- Cases: GET/POST /cases

Example create payloads:

- POST /users
```json
{
  "name": "Alice",
  "email": "alice@example.com",
  "password": "secret",
  "rfid_tag": "RF123"
}
```

- POST /items
```json
{ "description": "Black wallet", "status": "available" }
```

- POST /boxes
```json
{ "location": "Lobby", "status": true }
```

- POST /cases
```json
{ "box_id": 1, "item_id": 1, "status": "available" }
```

## DB Schema

The SQLite DB is created automatically at startup with tables: users, items, boxes, cases, matching the provided design (auto-increment PKs, FKs, uniques, timestamps with default now()).
